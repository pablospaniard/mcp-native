# `1.0.0` release readiness

MCP Native `0.9.1` is the feature-complete release candidate for the documented React Native host
scope. It is ready to install, evaluate, and integrate today. This checklist tracks the narrower
work required to promote that implemented contract to a reviewed `1.0.0` release.

## Automated release evidence

| Gate                          | Current evidence                                                                                                                                                                                                                                             |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Protocol and runtime behavior | `npm run check` runs formatting, linting, typechecking, the public API baseline, pinned schema verification, unit and integration coverage, hostile-input and fuzz coverage, performance and retained-memory budgets, and pinned MCP conformance.            |
| Public API                    | `npm run api:verify` compares every public export and generated declaration with the frozen release-candidate baseline.                                                                                                                                      |
| Package contents              | `npm run package:smoke` packs all six public workspaces, verifies every declared export, runtime and declaration source map, README, and exact MIT license, then installs the tarballs into a clean offline consumer and imports each supported entry point. |
| React Native support matrix   | Pull requests generate, bundle, and build hosts for React Native `0.87.0` and `0.87.1`, with Hermes and community JavaScriptCore, on Android and iOS.                                                                                                        |
| Release trust boundary        | The protected release workflow resolves an immutable stable tag, reruns release verification, and publishes in dependency order with npm trusted publishing and provenance. Interrupted releases can resume without overwriting an existing version.         |

## Remaining promotion work

These are release decisions and reviews, not missing product foundations:

- complete and record independent security, public API, protocol/schema, accessibility, and native
  WebView isolation reviews, resolving any release-blocking result;
- run the final end-to-end release-candidate evidence set and verify upgrade behavior from the
  latest published `0.9.x` packages;
- remove the deprecated custom A2UI `0.1` aliases from package roots while retaining the documented
  `/legacy` migration entry points, then approve the intentional public API baseline change;
- perform the final documentation and release-note review and adopt the published `1.x`
  compatibility promise;
- set the coordinated package versions to `1.0.0`, publish through the protected workflow, and
  verify npm contents, dist-tags, provenance, and clean installation from the registry.

The [roadmap](roadmap.md) is the authoritative milestone definition. The
[compatibility policy](compatibility-policy.md), [support matrix](support-matrix.md),
[migration guide](migration-to-1.0.md), and [release process](releasing.md) define the contract that
the final review promotes.
