# `1.0.0` release readiness

The MCP Native 0.9 line contains the validated low-level React Native, MCP, A2UI, MCP Apps, and policy
boundaries planned for 1.0 and is ready to install, evaluate, and integrate. Milestone 10 now includes
a high-level `@mcp-native/host` package that composes those boundaries into one connect-call-render
workflow. The remaining reviews and release decisions tracked here precede the long-term 1.x
compatibility promise.

## Automated release checks

| Gate                          | Current check                                                                                                                                                                                                                                                                                                          |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Protocol and runtime behavior | `npm run check` runs formatting, linting, typechecking, the public API baseline, pinned schema verification, unit and integration coverage, hostile-input and fuzz coverage, performance and retained-memory budgets, and pinned MCP conformance.                                                                      |
| Public API                    | `npm run api:verify` compares every public export and generated declaration with the frozen release-candidate baseline.                                                                                                                                                                                                |
| Package contents and upgrade  | `npm run package:smoke` packs all seven public workspaces and verifies every declared export, runtime and declaration source map, README, and exact MIT license. It upgrades all seven published packages from coordinated `0.9.x` versions to local candidate tarballs before exercising every supported entry point. |
| Native host integration       | Pull requests generate, bundle, and build a pinned default-engine host on Android and iOS. The fixture version supplies reproducible integration evidence rather than a package peer boundary.                                                                                                                         |
| Release trust boundary        | The protected release workflow resolves an immutable stable tag, reruns release verification, and publishes in dependency order with npm trusted publishing and provenance. Interrupted releases can resume without overwriting an existing version.                                                                   |

## Remaining promotion work

The headless host controller now owns connection, automatic discovery, calls, result resolution,
cancellation, reconnect, stale-result rejection, and teardown. Its React Native entry point owns the
mounted lifecycle and safe A2UI, MCP Apps, ordinary, and fixed host-state rendering. One application
policy authorizes A2UI and MCP Apps actions through their separate protocol delivery paths. The
remaining work is confidence, compatibility, migration, and publication:

- review the `@mcp-native/host/react-native` provider/result renderer and its accessible loading,
  empty, error, ordinary-content, A2UI, and isolated MCP Apps states as part of the stable API audit;
- preserve every existing low-level package as a separately usable path and keep custom contract
  registration out of v1; the post-1.0 roadmap owns versioned standard and application-defined input
  adapters;
- add focused clean-consumer, official-SDK, malformed-input, lifecycle, package-smoke, and upgrade
  checks for the new package, run locally or in CI;
- complete independent security, public API, protocol/schema, accessibility, and native WebView
  isolation reviews, resolving any release-blocking result;
- run the final end-to-end release-candidate checks;
- perform the final documentation and release-note review and adopt the published `1.x`
  compatibility promise;
- set the coordinated package versions to `1.0.0`, publish through the protected workflow, and
  verify npm contents, dist-tags, provenance, and clean installation from the registry.

Release verification is execution, not a repository artifact requirement. Maintainers summarize
the checks and review outcome in the pull request or release; raw logs, screenshots, generated
applications, reports, matrices, and transcripts do not need to be committed solely as release
evidence.

The [roadmap](roadmap.md) is the authoritative milestone definition, including the complete
