# `1.0.0` release readiness

MCP Native provides validated low-level React Native, MCP, A2UI, MCP Apps, and policy boundaries,
plus a high-level `@mcp-native/host` package that composes those boundaries into one
connect-call-render workflow. The v1 implementation, public API, documentation, and readiness
decisions are complete. The adopted [1.x compatibility policy](compatibility-policy.md) covers all
seven packages. Coordinated stable publication is the only open release gate.

## Automated release checks

| Gate                          | Current check                                                                                                                                                                                                                                                                                                        |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Protocol and runtime behavior | `npm run check` runs formatting, linting, typechecking, the public API baseline, pinned schema verification, unit and integration coverage, hostile-input and fuzz coverage, performance and retained-memory budgets, and pinned MCP conformance.                                                                    |
| Public API                    | `npm run api:verify` compares every public export and generated declaration with the finalized v1 baseline.                                                                                                                                                                                                          |
| Package contents and upgrade  | `npm run package:smoke` packs all seven public workspaces and verifies every declared export, runtime and declaration source map, README, and exact MIT license. It upgrades all seven published packages from coordinated `0.9.x` versions to local release tarballs before exercising every supported entry point. |
| Native host integration       | Pull requests generate, bundle, and build a pinned default-engine host on Android and iOS. The fixture version supplies reproducible integration evidence rather than a package peer boundary.                                                                                                                       |
| Release trust boundary        | The protected release workflow resolves an immutable stable tag, reruns release verification, and publishes in dependency order with npm trusted publishing and provenance. Interrupted releases can resume without overwriting an existing version.                                                                 |

The primary CI lane runs at the exact Node `22.12.0` floor. Support-matrix regression coverage also
locks the declaration toolchain and schema package, verifies the React and MCP SDK peer boundaries,
and rejects Expo, React Native, or React Native WebView as public package dependencies.

## Completed readiness decisions

- The high-level host and every focused package have finalized v1 APIs.
- The independent security, public API, protocol/schema, accessibility, and native WebView isolation
  reviews are complete, and all findings are resolved.
- Repository checks, package installation and upgrade checks, and native integration readiness are
  accepted for v1. The maintainer has closed the high-level iOS/Android walkthrough item as a
  release-readiness decision.
- The documentation and `1.x` compatibility contract are finalized. Custom contract registration,
  direct SwiftUI and Compose renderers, and the broader capability-provider framework remain
  post-v1 scope.

## Stable publication

- [x] Prepare all seven coordinated package versions and internal dependencies at `1.0.0`, stable
      install commands, and release notes.
- [ ] Run `npm run release:verify` and verify the `v1.0.0` tag against the final release commit.
- [ ] Publish through the protected workflow after maintainer review, then verify npm contents,
      dist-tags, provenance, and clean installation from the registry.

The manifests and release workflow track package versions and registry tags separately from the
finalized API contract.

Release verification is execution, not a repository artifact requirement. Maintainers summarize
the checks and review outcome in the pull request or release; raw logs, screenshots, generated
applications, reports, matrices, and transcripts do not need to be committed solely as release
evidence.

## Sign-off review findings

All findings from the five independent reviews (Security, Public API, MCP/A2UI/MCP Apps
protocol-schema conformance, Accessibility, and Native WebView isolation) are resolved:

- **Accessibility** — added the optional `onAnnounce` callback so hosts can wire host-state
  changes into `AccessibilityInfo.announceForAccessibility`; added busy state during loading,
  assertive live region on errors, a retry action on failed tool calls, a short fixed
  announcement for ordinary results instead of the full result text, and a generic fallback
  accessibility label for unlabeled `Image`/`Icon` components. Scoped
  `docs/native-accessibility-testing.md`, `docs/host-integration-checklist.md`, and
  `docs/wcag-2.2-native-assessment.md` to describe the actual mechanism and coverage.
- **Security** — preserved the stable MCP Apps `resourceDomains` mapping across image, script,
  stylesheet, media, and font directives while documenting its executable-resource and
  exfiltration trust; contained `onError` callback failures in the action dispatcher;
  documented the `frameDomains` CSP-only scope; rewrote A2UI v1 cycle rejection as an iterative
  worklist so it is stack-safe at the maximum component count.
- **Native WebView isolation** — pinned
  `injectedJavaScriptBeforeContentLoadedForMainFrameOnly: true` on the MCP Apps WebView bridge
  bootstrap so it cannot execute in a sub-frame.
- **Protocol / schema conformance** — documented the deliberate `supportedCatalogIds`
  stricter-than-schema enforcement and the rejected-but-undocumented `callRendererFunction`/
  `agentFunctionResponse` message kinds in `docs/a2ui-v1-conformance.md`; documented the manual
  verification process for the MCP Apps upstream commit pin in `docs/mcp-apps-compatibility.md`.
- **Public API** — documented the `@mcp-native/host` composition path (`McpNativeHostController`,
  `McpNativeHostProvider`, `createMcpNativeHostActionAuthorization`, `McpNativeHostResultView`) in
  `docs/host-integration-checklist.md` alongside the low-level path; documented how to discriminate
  host callback error shapes; fixed a malformed markdown table in `packages/mcp/README.md`.

The public API changes add optional accessibility fields and the required literal
`injectedJavaScriptBeforeContentLoadedForMainFrameOnly: true`; the
[migration guide](migration-to-1.0.md) documents the wrapper update. The refreshed baseline
(`docs/public-api-baseline.json`, `npm run api:verify`) and the full `npm run check` gate
(formatting, linting, typechecking, public API baseline, schema verification, unit and integration
tests, and MCP conformance) pass.
